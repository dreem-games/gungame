# GunGame

Top-down шутер от третьего лица в браузере.
Игра переписана с Java (LibGDX) на современный веб-стек: **TypeScript, Vite и Phaser 4**. В качестве физического движка используется **Matter.js**.

## Игра на сервере

| Версия | Адрес | Источник |
| --- | --- | --- |
| Production | [production.gungame.obergodmar.ru](https://production.gungame.obergodmar.ru/) | Ветка `web` |
| Preview ветки `web` | [branch-web-4b5e57f6.gungame.obergodmar.ru](https://branch-web-4b5e57f6.gungame.obergodmar.ru/) | Та же ветка `web`, отдельная инсталляция |
| Preview другой ветки | `https://branch-<slug>-<hash>.gungame.obergodmar.ru/` | Последний подходящий коммит ветки |
| Релиз | `https://release-v<MAJOR>-<MINOR>-<PATCH>.gungame.obergodmar.ru/` | Тег `vMAJOR.MINOR.PATCH` |

Для входа браузер запрашивает логин и пароль (HTTP Basic Auth). Данные доступа выдаёт владелец сервера отдельно;
в репозитории они не публикуются.

Например, тег `v1.2.3` соответствует адресу `https://release-v1-2-3.gungame.obergodmar.ru/`.
Это пример формата: адрес заработает, когда такой поддерживаемый тег действительно появится в репозитории.
Старые теги `v0.1` и `v0.1-dev` этой схемой не поддерживаются.

### Как получить адрес ветки

`slug` — имя ветки в нижнем регистре: последовательности символов, кроме `a–z` и `0–9`, заменяются на `-`,
крайние дефисы удаляются. Пустой результат заменяется на `branch`; длинное имя обрезается до 47 символов,
после чего удаляются крайние справа дефисы. `hash` — первые 8 hex-символов SHA-256 **исходного имени ветки**,
с учётом регистра и без завершающего перевода строки. Это хеш имени, а не коммита; URL ветки остаётся постоянным.

Команда из корня проекта выводит точный адрес для указанной ветки:

```bash
node - feature/new-map <<'NODE'
const { createHash } = require('node:crypto');
const branch = process.argv[2];
const normalized = branch.toLowerCase().replace(/[^a-z0-9]+/g, '-').replace(/^-+|-+$/g, '') || 'branch';
const slug = normalized.slice(0, 47).replace(/-+$/g, '') || 'branch';
const hash = createHash('sha256').update(branch).digest('hex').slice(0, 8);
console.log(`https://branch-${slug}-${hash}.gungame.obergodmar.ru/`);
NODE
```

Для `feature/new-map` результат — `https://branch-feature-new-map-9a52084e.gungame.obergodmar.ru/`.
Сама ветка должна существовать в GitHub; создание произвольного URL не создаёт ветку или релиз.

### Как появляется и обновляется инсталляция

- Push ветки или создание поддерживаемого тега запускает сборку в GitHub Actions. Frontend и backend берутся
  из одного коммита; артефакты публикуются в GitHub Releases.
- Первое открытие адреса после авторизации запрашивает развёртывание. Если артефакта ещё нет, сервер может
  запросить его сборку. Пока версия готовится, показывается страница состояния; готовность не мгновенная.
- Уже активированные production и preview веток автоматически следуют новым подходящим коммитам своих веток.
  Релизная инсталляция привязана к коммиту тега. У каждой инсталляции отдельный игровой backend.
- Поддерживаются коммиты, содержащие deployment-baseline
  `75dc118083ad0ac017837c68df1c76ccafa5845c`. Старые или несовместимые ветки не разворачиваются.
- Адрес неизвестной ветки или неподдерживаемого релиза показывает страницу «Сборка не найдена».

## Запуск проекта
Проект является веб-приложением. Для быстрого старта необходим Node.js.
```bash
npm install
npm run dev
```
После этого игра будет доступна в браузере (обычно по адресу `http://localhost:5173`).
